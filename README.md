# docs

Docusaurus site for my public projects' documentation, deployed to Cloudflare
Pages at `docs.jjsm.science`. The homepage (`/`) is a custom page with a
project grid; each project's actual docs live under its own route.

```text
docs/                              # this repo
├── docusaurus.config.js           # one plugin-content-docs instance per project
├── _quarto.yml                    # lets `quarto render` find every project's
│                                   # .qmd/.ipynb via their _metadata.yml
├── src/
│   ├── pages/index.js             # homepage: hero text + project grid
│   ├── components/{ProjectCard,ProjectsGrid}/
│   └── data/projects.js           # one entry per card shown on the homepage
├── varistar/
│   ├── sidebars.js
│   └── docs/{_metadata.yml, intro.md, ...}
├── env-maker/{sidebars.js, docs/}
├── ogle/{sidebars.js, docs/}
└── .github/workflows/deploy.yml   # quarto render -> docusaurus build -> Cloudflare Pages
```

## Routing

- `/` — the homepage (`src/pages/index.js`), a project grid driven by
  `src/data/projects.js`.
- `/varistar`, `/env-maker`, `/ogle` — each its own `plugin-content-docs`
  instance (config in `docusaurus.config.js`), with its own autogenerated
  sidebar under `<project>/docs/`.

The navbar deliberately has no links between projects — it only shows the
site title (→ home) and social links. Each project's docs are only
navigable via their own sidebar, so browsing `/varistar` never surfaces
`env-maker` or `ogle`. This is what keeps each project's docs section
independent while still living in one Docusaurus app.

## Docs content: Quarto

Each project's `docs/_metadata.yml` sets `format: docusaurus-md` +
`execute.freeze: auto`, so any `.qmd` / `.ipynb` file dropped into that
folder gets rendered to Docusaurus-flavored markdown by `quarto render`
before the Docusaurus build runs. Plain `.md` files (like the `intro.md`
placeholders) are left alone by Quarto.

## Adding a new project

1. Add a `src/data/projects.js` entry with `title`, `description`, `url`
   (`/<name>/intro` once it has docs, or an external link if not yet),
   `labels`, etc.
2. Once it has real docs: add `<name>/sidebars.js` (copy an existing one)
   and `<name>/docs/_metadata.yml` + at least one page, plus one more
   `@docusaurus/plugin-content-docs` block in `docusaurus.config.js`
   (`id`, `path: "<name>/docs"`, `routeBasePath: "<name>"`, `sidebarPath`).

`airac-tools` and `html2wikijs` currently have homepage cards pointing at
external subdomains and haven't been migrated into this repo yet — do that
by following step 2 above.

## Local dev

```sh
bun install
quarto render   # no-op until a project has .qmd/.ipynb files
bun run start   # http://localhost:3000
```

## Build & deploy

```sh
quarto render && bun run build   # -> build/
```

`.github/workflows/deploy.yml` runs this on every push to `main` and
deploys `build/` to Cloudflare Pages via `wrangler`. It needs
`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repo secrets, and its
`--project-name` should match your actual Cloudflare Pages project (create
it once via dashboard → Workers & Pages → Create → Pages → "Upload assets",
no build command needed there since CI does the building).
